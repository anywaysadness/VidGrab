# План доработок VidGrab

**Статус:** реализовано в версии 1.0.1.
**Повод:** пользователь получил `HTTP Error 403` на публичном видео YouTube, а приложение показало «Видео недоступно: приватное, удалённое или требует авторизации / не обходит DRM». Ошибка вводит в заблуждение и выглядит как искусственное ограничение.

## 1. Что на самом деле произошло

Из лога `%APPDATA%\VidGrab\vidgrab.log`:

```
[youtube] No supported JavaScript runtime could be found...
[info] Downloading 1 format(s): 400+251-1
ERROR: unable to download video data: HTTP Error 403: Forbidden
...
Ошибка пользователю: Видео недоступно: приватное, удалённое или требует авторизации...
```

Причины две, и обе исправимы:

1. **Нет JS-рантайма.** yt-dlp 2026 для YouTube решает JS-задачи (nsig/PO-token). Без рантайма включается упрощённый клиент `visionos`, который отдаёт ссылки, падающие с 403 в процессе загрузки. Проверено локально: с QuickJS-ng 0.17.0 то же видео скачивается полностью и склеивается.
2. **Слишком грубая классификация ошибок.** Любой `HTTP Error 403` и `Sign in to confirm you're not a bot` попадают в маркер «недоступно/приватное/DRM», хотя видео публичное.

**Граница работ:** приложение не содержит и не будет содержать обхода DRM/платных подписок — это техническое и правовое ограничение, а не «защита», которую можно выключить. Убираем ложные блокировки, вводящие в заблуждение тексты и добавляем законные способы авторизации (cookies).

## 2. Требования и решения

| № | Требование | Решение |
|---|---|---|
| R1 | Убрать «встроенную защиту» и ограничения | Убрать из пользовательских ошибок формулировки «приложение не обходит DRM/авторизацию»; убрать ложное `unavailable` для 403, bot-check и ошибок формата. Дисклеймер сократить до одной нейтральной строки. Реальный обход DRM не добавляется |
| R2 | Кнопка «Открыть папку» всегда доступна | Не скрывать и не дизейблить; открывать **текущую папку из поля «Папка сохранения»**, а не путь последнего файла. Если поле пустое — папка по умолчанию (`Downloads\VidGrab`); если папки нет — создать и открыть. Ошибка — только если систему реально нельзя открыть |
| R3 | После каждого видео — ссылка на папку, кликабельная | Панель результата под прогрессом: имя файла + ссылка `file:///...` на папку; клик открывает Проводник. Ссылка живёт до следующей загрузки, при ошибке/отмене скрывается. **После перезапуска приложения ссылка не восстанавливается** (никакого «помнит последний файл»). Если файл к моменту клика уже перемещён/удалён — не показывать ошибку, а просто открыть папку загрузки (выбранную в поле, иначе `Downloads\VidGrab`). Историю загрузок не делаем |
| R4 | Кнопка формирования отчёта по логам | Кнопка «Отчёт» в окне (доступна всегда). Создаёт `%APPDATA%\VidGrab\reports\report-ГГГГММДД-ЧЧММСС.txt`: версия, ОС, Python/Qt/yt-dlp/ffmpeg/qjs, настройки (без cookies), последние ~500 строк лога, результат selftest. Показывает путь и кнопку «Открыть папку с отчётом». Никуда не отправляется |
| R5 | После ошибки/отмены прогресс не «висит» | На ошибке и отмене: `range 0..100`, `value 0`, проценты/скорость/ETA в исходное состояние, статус ошибки; на старте новой загрузки — снова 0. Добавить тесты на оба сценария |
| R6 | Понятные ошибки вместо traceback-пугала | Коды: `bot_check`, `forbidden`, `format_unavailable`, `drm`, `network`, `permission`, `ffmpeg`, `generic`. Для `bot_check` — текст «YouTube просит подтвердить, что вы не бот. Включите cookies браузера в настройках или повторите позже» + кнопка «Открыть настройки» |
| R7 | Не ограничивать пользователя | Добавить cookies: `cookies_from_browser` (Chrome/Edge/Firefox) и/или `cookies.txt`, пробрасывать в yt-dlp (`cookiesfrombrowser` / `cookiefile`). Это авторизация, а не обход DRM. Опционально — выбор клиента YouTube в настройках (advanced) |

## 4. Порядок работ

### Этап 1. YouTube: JS-рантайм и ошибки
- Скачать QuickJS-ng 0.17.0 (`qjs.exe`, ~1.5 МБ), положить в `vidgrab/assets`, добавить в сборку.
- `find_quickjs()` + `js_runtimes` в опциях yt-dlp.
- Проверить на реальном видео `dO-mJjZfwxE`: загрузка до конца, склейка, файл на диске.
- Переписать `describe_error`: отдельные `bot_check`, `forbidden`, `format_unavailable`, `drm`, `unavailable` (только приватное/удалённое/вход), `network`.
- Убрать из UI фразы про «не обходит DRM/авторизацию».
- **Выход:** нет ложного «видео недоступно» на 403; bot-check объясняется и решается cookies.

### Этап 2. Открыть папку и ссылка результата
- «Открыть папку» видна и активна всегда; берёт `folder_edit` (нормализует, создаёт при необходимости), не `_last_path`.
- После успеха — строка результата: `Файл: <имя>` и ссылка `Открыть папку` (`file:///`), клик → Проводник.
- При старте новой загрузки/ошибке/отмене строка скрывается; после перезапуска не восстанавливается.
- Клик по ссылке/кнопке: если файл ещё существует — открыть его папку; если файла нет — открыть папку загрузки; если нет и папки — `Downloads\VidGrab`, создать. Никаких ошибок из-за удалённого файла.
- **Выход:** смена папки в поле меняет, куда ведёт кнопка; удаление файла не ломает открытие папки; после перезапуска старая ссылка не висит.

### Этап 3. Прогресс и отмена
- Сброс прогресса на `failed` и `cancelled`; сброс индикаторов; убрать «35%» после ошибки.
- Тесты: сбой на середине, отмена, повторный старт.
- **Выход:** после ошибки/отмены прогресс 0%, метки «—», кнопки в исходном состоянии.

### Этап 4. Отчёт по логам
- Кнопка «Отчёт» → сбор данных → файл в `%APPDATA%\VidGrab\reports` → путь + «Открыть папку».
- В отчёт не попадают cookies/токены; URL и пути — попадают (для диагностики).
- **Выход:** отчёт создаётся при любом состоянии, открывается папка, selftest включён.

### Этап 5. Cookies и настройки
- Диалог «Настройки»: источник cookies (нет / Chrome / Edge / Firefox / файл), путь к cookies.txt, клиент YouTube (auto/web/tv).
- Проброс в yt-dlp; проверка на видео, требующем входа/подтверждения.
- Понятная ошибка, если браузер не найден/профиль зашифрован.
- **Выход:** bot-check проходит с cookies Chrome (или ошибка объясняет, что сделать).

### Этап 6. Сборка и релиз
- Версия **1.0.1** (или 1.1.0), пересборка exe, `--selftest`, прогон тестов.
- Новый ZIP `VidGrab-1.0.1-win64.zip` + SHA-256; обновить README.
- В GitHub: либо заменить ассет в v1.0.0 (проще, но кэш), либо опубликовать v1.0.1 и пометить v1.0.0 как старую. Рекомендуется **v1.0.1**.

- [x] При bot-check сообщение объясняет причину и предлагает cookies, а не «приватное/DRM».
- [x] «Открыть папку» видна всегда и открывает папку из поля, даже если загрузки не было.

- [x] Если файл удалён/перемещён, ссылка/кнопка открывает папку загрузки, а не ошибку.

- [x] После ошибки и отмены прогресс 0%, ничего не «висит».
- [x] Кнопка «Отчёт» создаёт файл, путь виден, папка открывается.

## 6. Риски и ограничения

- YouTube часто меняет защиту: qjs исправляет текущий 403, но через месяцы может понадобиться обновление yt-dlp/qjs.
- Cookies — чувствительные данные: хранить только путь/браузер, не копировать содержимое в отчёт и логи.
- DRM-контент (Netflix и т.п.) по-прежнему не поддерживается: обход DRM не реализуем.
- Клик по ссылке `file:///` в Qt может требовать `QDesktopServices.openUrl` вместо HTML-ссылки; проверить на Windows.
- «Помнит последнюю ссылку» не должно превращаться в хранение пути к файлу в настройках: сохраняем только папку (`last_folder`).
- Отчёт с URL/путями может содержать личные данные — предупредить пользователя.

## 7. Принятые решения

1. История загрузок не нужна: остаётся ссылка на последнее видео, после перезапуска не восстанавливается.
2. Cookies: браузеры Chrome/Edge/Firefox и файл `cookies.txt` (оба варианта).
3. Отчёт — текстовый файл (лог + selftest + настройки без cookies).
4. Версия релиза — 1.0.1.
